============================================================
TARGET 1 — SILENT WINDOWS AUTOSTART
===================================

PRODUCT GOAL

ProTrail should optionally start automatically with Windows.

When started by Windows:

* launch silently;
* start minimized / tray-only;
* do not open Settings;
* do not steal keyboard focus;
* do not flash a normal application window;
* do not create a visible taskbar button;
* do not require administrator privileges;
* normal configured effects should become active according to saved state.

Add a user-facing setting:

Start with Windows

This is an essential setting and must also be available from the Main UI Essentials surface described later.

IMPLEMENTATION

Use per-user Windows autostart.

Preferred mechanism:

HKCU\Software\Microsoft\Windows\CurrentVersion\Run

Use a stable ProTrail-owned registry value name.

Register the fully quoted current executable path with an explicit startup argument, for example conceptually:

--startup-minimized

The exact argument naming may follow existing command-line conventions.

AUTOSTART INVOCATION CONTRACT

Normal manual launch:

* preserve current behavior.

Windows autostart launch:

* detect startup argument;
* initialize normal product services;
* initialize tray;
* initialize effect/render infrastructure;
* do not show Settings/Main window automatically;
* remain non-activating.

If overlays are needed for effects, those overlay windows remain click-through/non-activating according to current architecture.

Do not fake minimization by showing the main window and immediately hiding it.

Avoid the visible flash entirely.

SINGLE INSTANCE

Autostart must respect the existing single-instance contract.

If ProTrail is already running when the startup invocation arrives:

* do not create a second process instance;
* do not unexpectedly open the Main/Settings UI merely because the second invocation came from autostart;
* exit/forward according to existing single-instance architecture.

REGISTRY RECONCILIATION

When Start with Windows is enabled:

* registry command must reference the actual current executable path;
* if the portable application moves and later runs manually from a new location, reconcile the registered path safely.

When disabled:

* remove only ProTrail's own autostart value;
* never modify unrelated startup entries.

No administrator elevation.

TESTABILITY

Abstract registry access behind a small testable platform-owned component.

Unit tests must not modify the real user's Run key.

Test:

* enable creates correct quoted command;
* disable removes only owned value;
* path containing spaces is quoted correctly;
* moved executable updates owned command;
* repeated enable is idempotent;
* repeated disable is idempotent;
* startup-mode command line selects silent path;
* startup-mode does not request the Main/Settings window.

MIGRATION

Autostart introduces an OS side effect.

For configurations created before this feature:

Start with Windows = OFF

Do not silently enroll an existing upgraded user into Windows startup.

Fresh-install behavior is controlled by the Release Defaults system below.

TARGET 2 — CANONICAL RELEASE DEFAULTS
=====================================

PRODUCT GOAL

The developer must be able to tune ProTrail interactively and then save the CURRENT COMPLETE SETTINGS STATE as the defaults that future release installations use.

The user explicitly wants a developer button/panel for this.

This must eliminate scattered, drifting hard-coded product defaults.

CREATE ONE CANONICAL RELEASE DEFAULT SOURCE

Introduce a canonical file such as:

resources/release_defaults.json

Exact location may follow repository conventions.

This becomes the authoritative semantic default configuration for a fresh installation.

It must contain every persisted user-facing setting that is appropriate for a new user.

Examples include:

* Trail settings;
* Trail Style;
* sparkle settings;
* Click settings;
* ClickStyle;
* Hold settings;
* Motion Wake settings;
* application behavior settings;
* Start with Windows desired default;
* all future user-visible configuration fields.

Do NOT store machine-specific runtime values such as:

* absolute executable path;
* registry path state;
* current process state;
* timestamps;
* migration metadata unrelated to product preference;
* transient animation state;
* active HOLD state;
* wake records;
* window handles;
* runtime diagnostics.

RELEASE DEFAULTS MUST DRIVE BOTH

1. fresh configuration creation;
2. Restore Defaults behavior.

There must not be one set of defaults in C++ and another in the release preset.

One semantic source of truth.

EMBED / PACKAGE

The production executable must not depend on a writable source-tree JSON existing beside it.

At build/package time:

* validate release_defaults.json;
* package/embed the validated defaults according to the existing resource architecture.

A missing or invalid Release Defaults source during a release build must fail visibly.

Do not silently produce a release using unknown fallback values.

A narrowly scoped emergency fallback may exist for corrupted runtime resources only if architecture requires it, but tests must prevent it from becoming a second drifting default authority.

100%

Suggested:

200%:

Do not expose the internal saturation speed unless genuinely necessary.

## MINIMUM MOTION SPEED

Minimum Speed

Suggested range:

0 .. approximately 1000 px/s

0:

any meaningful movement may emit wake.

This allows the user to configure:

Do not alter the HOLD aura.

The aura remains alive while held even when Wake emission is gated.

## TURN ACCENT

Toggle:

Turn Accent

ember fan.

Earth:

SparkBurst:

Use a bounded angular threshold/hysteresis.

Do not fire an accent on every tiny mouse jitter.

A sharp reversal may produce a stronger accent than a gentle curve.

Keep the exact creative math style-specific.

---

## STOP ACCENT

Toggle:

Stop Accent

When meaningful movement transitions into a stationary/near-stationary hold:

Examples:

Water:

Earth:
dust settle.

Air:

SparkBurst:
tiny electrical discharge.

Do not continuously emit Stop Accents while stationary.

One motion episode -> at most one stop transition accent.

Movement restarting arms the next Stop Accent.
