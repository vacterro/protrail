PRODUCT DIRECTION

The current HOLD system works, but its continuous style content remains visually attached to the current cursor position.

When the mouse moves, the visual field follows the cursor.

This can read like an animated GIF or sticker attached to the pointer.

The desired experience is different:

THE CURSOR IS AN EMITTER.

While a button is actively held and the cursor moves:

* the live HOLD aura may continue following the cursor;
* BUT the movement must continuously shed style-specific effects into WORLD SPACE;
* already-emitted effects remain anchored where they were born;
* those emissions continue animating and fading independently after the cursor has moved away;
* the cursor leaves visible consequences behind it.

The desired result is deliberately energetic and expressive.

The user explicitly wants the system to "throw particles/effects everywhere" in a controlled visual manner rather than looking mechanically attached to the mouse.

CORE VISUAL MODEL

Split HOLD rendering conceptually into three layers:

A. ATTACHED HOLD AURA

Lives at the current cursor.

Purpose:
show that the button is actively held and charged.

Existing T-24 style-aware aura mostly remains.

B. DETACHED MOTION WAKE

Generated while an ActiveHold moves.

Each emission receives a fixed world-space birth anchor.

After birth it NEVER follows the cursor.

Its subsequent animation is a pure function of:

* immutable birth anchor;
* birth timestamp;
* deterministic seed;
* style snapshot;
* movement tangent / speed snapshot;
* charge snapshot;
* relevant visual config snapshot.

C. RELEASE PAYOFF

Existing style-aware charged Up effect at the actual release location.

These three layers must visibly cooperate but remain lifecycle-independent.

T-26 ARCHITECTURE — IMMUTABLE WAKE EMISSIONS

Introduce a bounded wake-emission representation.

Conceptual data:

HoldWakeEmission {
world_x
world_y
birth_timestamp_ns
seed
style
tangent_x
tangent_y
motion_speed
charge
visual snapshot
}

Do not store evolving particle coordinates.

Do not integrate physics per frame.

Rendering remains:

geometry = f(emission, elapsed)

The only mutable part of wake generation is INPUT-DRIVEN emission bookkeeping.

Render-frame cadence must not affect the result.

WORLD-SPACE CONTRACT

Once an emission is born at:

(x, y)

that anchor is immutable.

Moving the cursor later must not move it.

Moving the HOLD aura later must not move it.

Changing the current Hold position must not move it.

This is the primary acceptance criterion of T-26.

DISTANCE-BASED EMISSION

Do NOT emit one packet per mouse event.

Mouse event frequency is not a visual unit.

Instead emit according to DISTANCE TRAVELLED.

Each active Hold tracks enough input-side state such as:

* last movement point;
* last movement timestamp;
* residual distance to next emission;
* deterministic wake ordinal.

For every movement segment:

previous_position -> new_position

walk along that segment at fixed configurable spacing.

Interpolate emission anchors along the actual segment.

For example:

spacing = 12 px

A 60 px movement may produce approximately five world-space emission anchors even if Windows delivered that movement in one sample.

A sequence of smaller input samples over the same geometric path should produce effectively the same spatial emission pattern.

Do not simply spawn all missing particles at the newest cursor position.

TIMESTAMP INTERPOLATION

When several anchors are generated from one movement segment, give them interpolated birth timestamps between the previous and current CursorSample timestamps.

This prevents a fast movement from creating a spatially distributed wake whose entire contents are artificially the same age.

BOUNDED FAST-MOTION POLICY

Very large cursor teleports must not generate thousands of emissions.

Add a bounded maximum number of wake births per movement sample.

Recommended:

kMaxWakeBirthsPerMovement = 12 or 16

If a movement requires more crossings than that:

sample/interpolate the segment deterministically across the allowed budget.

Do not create an allocation storm.

GLOBAL WAKE CAP

Wake memory and render cost must be hard bounded.

Recommended starting point:

kMaxWakeEmissions = 192 globally

or an equivalent bounded design.

Expired emissions prune first.

If overflow remains:

discard the oldest wake emission.

Do not remove active HOLD state merely because wake storage overflowed.

STYLE SNAPSHOT

A previously emitted wake must not transform because the user changes ClickStyle while it is fading.

Snapshot at birth at least the visual properties required to preserve identity:

* ClickStyle;
* color;
* element tint;
* particle amount where relevant;
* wake intensity;
* wake lifetime;
* size/radius basis;
* deterministic seed;
* charge;
* motion tangent/speed.

Changing Settings affects NEW emissions.

Old emissions finish according to the state they were born with.

T-26 MOTION ENERGY

Derive a bounded normalized motion factor from cursor speed.

Conceptually:

motion_energy = clamp(speed_px_per_sec / reference_speed, 0..1)

Use it as an artistic input.

It may influence:

* particle travel;
* lateral spread;
* size;
* local brightness;
* style-specific throw.

Do NOT use speed to remove the hard caps.

Slow movement should still create a readable wake.

Fast movement should feel more energetic.

STYLE-SPECIFIC MOTION WAKE GRAMMAR

Do NOT implement one generic dot trail with different colors.

Each ClickStyle must leave a recognizable wake.

RING

Wake:
small expanding ring stamps born along the path.

Behavior:
each ring remains at its original world coordinate and continues expanding/fading after the cursor leaves.

At slow movement:
clear sequence of echoes.

At fast movement:
more spatially separated pressure-ring marks.

DOUBLE RING

Wake:
paired concentric echo stamps.

The two rings expand at slightly different rates.

The cursor should leave a chain of paired resonances behind it.

RIPPLE

Wake:
world-space ripple sources.

Each anchor may emit 2-3 staggered small waves over its lifetime.

This should look like the cursor disturbed an invisible surface at every location it passed.

BURST

Wake:
small local micro-bursts.

Do not replay the full click explosion at every anchor.

Use a reduced style-specific packet:

* few particles;
* deterministic angular scatter;
* mild backward/side bias from movement tangent;
* short lifetime.

The cursor should leave tiny explosions behind it.

SPARKBURST

Wake:
aggressive crackling spark shedding.

More chaotic than Burst.

Use:

* stronger angular jitter;
* broader speed variation;
* per-particle lifetime variation;
* motion-direction bias;
* occasional hotter/faster spark.

This should be one of the most visibly alive HOLD trails.

SOFT FLASH

Wake:
soft fading afterglow puffs.

Not particles pretending to be SoftFlash.

Small translucent world-space glow discs remain where the cursor passed.

Overlap is allowed but must remain bounded.

The result should resemble an illuminated afterimage, not one disc attached to the cursor.

DOT RING

Wake:
bright detached beads plus occasional small ring echo.

Primary signature:
a chain of glowing nodes left behind the cursor.

Do not turn it into SparkBurst.

AIR

Wake:
shed tangential motes and small curling eddies.

Movement tangent matters strongly.

Suggested behavior:

* motes initially lag slightly behind motion;
* then curve sideways/tangentially;
* small vortex displacement continues after cursor departure.

The old world-space particles must visibly remain in place while curling.

AIR should look like the pointer moved through air and disturbed it.

FIRE

Wake:
embers continuously shed from the moving HOLD.

This is a key visual target.

Each world-space emission should create a few embers that:

* are born near the movement path;
* keep their birth anchor;
* rise upward independently;
* wobble;
* cool/fade with age.

Fast movement may throw embers slightly backward relative to motion before buoyancy takes over.

The cursor should leave a burning ember wake behind it.

WATER

Wake:
droplets plus local mini-ripple/splash anchors.

When moving:

* a few droplets are thrown from the path;
* droplets follow bounded arcs;
* a small ripple may remain at the emission point;
* old ripple anchors remain where they were born.

The result should resemble dragging a wet pointer across an invisible surface.

EARTH

Wake:
heavy dust and small debris.

Avoid orbiting.

Each emission may contain:

* short-lived dust puff;
* a few chunky particles;
* particles lag slightly behind movement;
* small deterministic ground-like tremble;
* gravity/downward settling.

The path should feel dirty/heavy.

Earth should visibly leave debris behind rather than escorting a constellation around the cursor.

STATIONARY HOLD

Do not generate an infinite stream of world-space wake emissions while the cursor is stationary.

The attached HOLD aura already provides stationary life.

Motion Wake exists primarily as a consequence of movement.

A very small style-specific stationary ambient cycle may remain part of the attached aura, but it must not continuously add persistent Wake records without movement.

START / STOP SEMANTICS

Before Hold activation threshold:

no wake.

Candidate state must never emit wake.

Once Candidate becomes ActiveHold:

wake generation begins from the current position.

On movement:
emit according to crossed distance.

On Up:

* stop creating new wake;
* existing wake emissions continue their independent fade;
* release payoff spawns normally.

Therefore after releasing the button the screen may still contain dying debris/embers/ripples from the motion path.

That is desired.

LOST-UP RECONCILIATION

If physical reconciliation cancels a lost-Up hold:

* stop future wake generation;
* do not create release payoff;
* existing already-born wake may finish naturally.

Do not instantly erase the visual history unless master/effect clear semantics explicitly require it.

MASTER / CLEAR SEMANTICS

Master OFF:
clear active holds AND all wake emissions immediately.

Click FX OFF:
clear active holds AND all wake emissions.

Explicit clear/shutdown:
clear everything.

Hold FX OFF:
cancel Candidate / ActiveHold.

Recommended:
also clear its remaining Hold Wake immediately, because the user explicitly switched Hold FX off.

Motion Wake OFF:
stop creating new wake and clear currently alive wake emissions so the setting response is visually immediate.

SCHEDULER

Wake emissions are live visual content.

The active-only scheduler must remain awake while ANY of these exist:

* ordinary click bubbles;
* Hold candidates;
* active Hold aura;
* Hold Motion Wake emissions;
* release payoff;
* Trail content.

Once all expire:

scheduler returns to idle behavior.

No new idle wake loop.

WAKE DENSITY MAPPING

Do not interpret density as "particles per frame."

Map it to spatial emission spacing.

Conceptually:

higher density -> smaller spacing
lower density  -> larger spacing

Example starting mapping:

density 0.25 -> approximately 32 px spacing
density 1.00 -> approximately 12 px spacing
density 2.00 -> approximately 6 px spacing

Use a smooth bounded mapping.

Existing Click particle_amount remains the style's within-emission particle budget.

Wake Density controls HOW OFTEN spatial emission packets are created.

These are different concepts.

HOLD INTENSITY

Hold Intensity primarily scales the attached aura.

At 1.0:

WAKE LIFE

Scales detached wake lifetime.

It must not alter release duration or ordinary click duration.

Each wake emission snapshots the configured wake lifetime at birth.

Changing Wake Life while old emissions exist must not retroactively stretch/shrink them.

RELEASE STRENGTH

final_release_power =

At 1.0:
current accepted T-24 release behavior.

At lower values:
smaller discharge.

At higher values:
stronger spatial/size payoff.

Particle count remains bounded by existing budgets.
