TARGET A — FIX VARIABLE-LIFETIME SCHEDULER FALSE-IDLE

ROOT CAUSE

ClickBubbleEffect::has_live_wake() currently assumes:

the newest wake emission is always the last one to expire.

It therefore checks only:

wake_.back()

That assumption became false in T-27 because each HoldWakeEmission snapshots its own:

lifetime_ms

Wake Life may change while older emissions are still alive.

Failure example:

1. Existing emission A:
   lifetime = 2500 ms

2. User changes Wake Life:
   150 ms

3. New emission B:
   lifetime = 150 ms

4. B expires.

5. A is still alive.

Current has_live_wake() sees dead wake_.back() == B and returns false.

The active-only scheduler may therefore sleep while A still has live animation.

This can leave old wake visually frozen or stop it before its intended lifetime.

REPAIR

Do not infer liveness from birth ordering.

has_live_wake(now_ns) must answer:

Does ANY stored wake emission still have progress < 1?

Use a bounded scan across wake_.

The vector is hard-capped at 192 records, so O(192) for the scheduler content gate is bounded and acceptable.

Alternative cached lifetime ordering is unnecessary complexity.

Preserve immutable emission semantics.

TESTS

Add regression:

* create long-life wake emission A;
* change config to short Wake Life without clearing existing wake;
* create short-life newer emission B;
* choose now where:

  * B is expired;
  * A is still alive;
* has_live_wake(now) must be true;
* has_live_content(now) must be true;
* after A also expires, both must become false.

Also test the inverse:

* old short-life emission;
* new long-life emission;
* normal behavior remains correct.

Do not clear wake merely because Wake Life changed.

Existing emissions must keep their birth-snapshotted lifetime.

TARGET B — CLIP MOVEMENT AT THE HOLD ACTIVATION BOUNDARY

ROOT CAUSE

on_cursor_moved() currently decides whether an entire movement segment may emit using:

is_active_at(hold, sample.timestamp_ns)

This only checks the END timestamp.

A movement sample may straddle activation.

Example:

Down:
0 ms

Previous movement:
160 ms

Current movement:
200 ms

Activation:
175 ms

The segment 160 -> 200 crosses the activation boundary.

Current code sees that the hold is active at 200 ms and walks the WHOLE segment.

Interpolated emissions may therefore receive:

birth_timestamp_ns < 175 ms

and anchors from movement that occurred while the gesture was still a Candidate.

That violates:

Candidate never emits wake.

REPAIR

For every movement segment:

prev_position / prev_timestamp
->
new_position / new_timestamp

calculate the activation timestamp:

activation_ns =
hold.start_timestamp_ns

* kHoldActivationMs

Cases:

1. Entire segment before activation:
   no wake.

2. Entire segment after activation:
   current distance logic unchanged.

3. Segment crosses activation:
   clip the eligible wake segment to activation_ns -> current timestamp.

Interpolate the cursor coordinate at activation_ns along the movement segment.

Use that interpolated activation point as the wake-emission segment start.

Only post-activation distance may contribute to:

* residual distance;
* emission anchors;
* birth timestamps;
* tangent/speed calculations used by those emissions.

No wake emission may ever have:

birth_timestamp_ns < activation_ns

Do not replay pre-activation movement.

The attached HOLD aura may still follow the cursor normally.

TESTS

Add explicit straddle tests.

Example:

Down at 0 ms / x=0.

Movement at 160 ms / x=0.

Movement at 200 ms / x=100.

Activation = 175 ms.

Assert:

* wake is allowed after activation;
* every wake birth timestamp >=175 ms;
* no anchor comes from the pre-activation portion of the segment;
* spatial residual is based only on eligible post-activation travel.

Test equivalent segmented delivery:

160 -> 175 -> 200

versus:

160 -> 200

The post-activation wake pattern must be equivalent within deterministic interpolation rules.

Also preserve:

* movement wholly before threshold emits zero;
* movement wholly after threshold behaves unchanged;
* stationary activation emits no detached wake.
